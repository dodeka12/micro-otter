# Changes since version 1.25.0

## New Features

- **A node whose add-on is gone says so** — a node whose type the active runtime no longer provides
  keeps its place in the graph and is painted with the capability-error border; hovering it names the
  package to install (`graph.nodeTypeMissing`, English and German). Reinstalling the package clears the
  issue on the next reload, because the type resolves again.
- **The palette follows installs and removals** — a successful add-on install or uninstall reloads the
  runtime collection in place and announces `RuntimeCollection.RuntimesLoaded.v1`, so the palette gains
  or drops the package's node types and the graph re-validates its nodes without a page reload.

## Improvements

- **The example add-ons ship their licence** — `hello` and `pulse` carry the repository `LICENSE`
  (GPL-3.0-only) inside the package, repeat the statement in every node's `info` text (which is what
  **Show Information** shows) and in their `README.md`, and the add-on authoring docs explain that no
  manifest entry is needed for a licence file.
- **A reload forgets what it no longer serves** — `DeviceRuntime` clears its cached package variants
  when it reloads its packages, so an uninstalled add-on stops answering variant queries in the
  Firmware tab.
- **The title bar shows the server state** — one `ServerConnectionMonitor` polls the capability
  endpoint (15 s while connected, 3 s while disconnected, paused while the tab is hidden) and an
  `Offline` badge appears in the title bar when the local server cannot be reached; clicking it
  reconnects, and after 15 s a dialog offers `Reconnect` (plus `Continue without server` in a dev
  build).
- **The Firmware tab stopped repeating itself** — the status badge, the server version, and the Retry
  header are gone, because the title-bar badge now owns server availability; an unreachable server
  shows one folded Help section, and a `ready` server that cannot compile or flash names each
  unavailable backend and its reason as diagnostic lines in the Build Firmware log.

## Fixes

- **Icons render without the server** — `IconProvider` serves every registered SVG inline as a
  `data:` URI (regenerated by `npm run generate:icons`), and the dev server answers
  `/html/icons/*` with a cacheable `Cache-Control`, so menus, toolbars, and the offline badge keep
  their icons while the local server is down. Every component that chooses between an `<img>` and a
  text/emoji glyph now asks `IconProvider.isImageSource()`, so an inlined icon is never printed as a
  base64 string (the tab strip was the visible case).
- **The palette kept the package list it read at start-up**, so a freshly installed add-on stayed
  invisible and an uninstalled one stayed clickable until the page was reloaded.
- **A node whose type stopped resolving silently lost its issues** instead of reporting the missing
  package; the red border it should have kept disappeared with them.
- **The offline badge only shows while the server is gone** — the badge borrowed the title bar's
  icon-button chrome, whose inline `display: flex` outranked the stylesheet's
  `.workspace-server-badge[hidden] { display: none }`, so a bare icon sat in the bar in every session
  (most visibly under `npm run dev`, where the app is served by Vite) and its tooltip claimed the
  server was unreachable while the Firmware tab worked. The badge now carries no inline style and
  takes both its look and its `[hidden]` visibility from `styles/standard/workspace-view.css`.
- **The Firmware tab opens its Help section when the server is unreachable** — an outage replaces the
  panes with one Help section, and that section now starts expanded, so the recovery text (*what the
  server adds*, `uv run micro-otter serve`) is what the empty tab shows instead of a header that
  needs another click. A collapse the user makes during the outage is still left alone.
